# Task 6 report: OpenAPI and typed client

## Status

Task 6 is complete in the `codex/oidc-rbac` worktree. The authenticated API
contract is published in generated OpenAPI and TypeScript declarations, and
the browser client now accepts request-time access-token and unauthorized
handlers without storing tokens. The requested commit is
`feat(auth): publish authenticated API contract`.

## Carried Task 5 breaker fix

The required pre-task fix is committed separately as `a95d3c1`
(`fix(cases): reject unnormalizable risk expiry values`). Its regression test
uses a `datetime` subclass with a valid `utcoffset()` but a failing
`astimezone()` conversion.

### RED

Before the fix, the service regression did not raise and the API regression
approved the decision (`200`) instead of returning the stable approval error.
The first API attempt against the stale local SQLite file exposed its known
missing-`request_id` schema; rerunning against a fresh migrated database
reproduced the intended `200` failure.

### GREEN

The approval validator now independently normalizes the persisted expiry to
UTC and maps conversion failures to `ValueError("risk decision expires_at
must be timezone-aware")`. The API maps this to `422 invalid_risk_approval`.
The service and API regressions assert unchanged case status/version, pending
decision state, and audit/outbox counts. Focused and full case/API suites pass
on a fresh database.

## Task 6 RED/GREEN evidence

### RED

The new contract tests initially failed because the runtime app had no
`securitySchemes`, no protected-operation security requirements, and no
request bodies for transition/risk request/approval. The new client tests
failed because no injectable token provider, 401 callback, or typed approval
method existed, and the old transition client still serialized `actor`.

### GREEN

- `HTTPBearer` metadata is attached through the authenticated principal
  dependency as `BearerAuth` (`bearer`, `JWT`).
- Every visible `/api/v1` operation carries the bearer requirement; health
  endpoints remain public.
- Authenticated operations publish normalized `ProblemDetails` responses for
  401 and 403.
- Transition, risk-request, and risk-approval OpenAPI request schemas contain
  no client identity fields. Runtime parsing remains inside the endpoint so
  cross-organization resource checks happen before body validation.
- The approval route has a typed request/response contract and the frontend
  client exposes `approveRiskDecision`.
- `configureApiClient` injects a token at request time and exposes one
  `onUnauthorized` callback. Only fetch/network failures receive the existing
  single retry; a 401 is normalized and never retried.
- Frontend transition and risk-request call sites no longer send actor,
  requester, or approver identity fields.

## Generated artifacts

OpenAPI was regenerated from a running Uvicorn app with explicit test
configuration:

```text
ENVIRONMENT=test AUTH_TEST_BYPASS_ENABLED=true \
OIDC_ISSUER_URL=https://issuer.example OIDC_AUDIENCE=vulnops-api \
DATABASE_URL=sqlite:///... \
uv run uvicorn vulnops.main:app --host 127.0.0.1 --port 18080
curl -fsS http://127.0.0.1:18080/openapi.json \
  | uv run python -c 'import json,sys,yaml; yaml.safe_dump(json.load(sys.stdin),sys.stdout,sort_keys=False,allow_unicode=True)' \
  > openapi/openapi.yaml
```

The generated declaration was then regenerated by the package script using
Node `v22.22.2`:

```text
cd frontend
corepack pnpm openapi
```

An independent check confirmed `openapi/openapi.yaml` is equal to
`create_app().openapi()` under the explicit test configuration.

## Self-review and concerns

- The API contract advertises bearer access tokens, while the browser login
  and PKCE lifecycle remain Task 7 work.
- Request schemas explicitly forbid unspecified extra keys in the published
  contract, so generated clients cannot send actor/requester/approver identity
  fields. Runtime parsing remains inside the endpoint so identity rejection
  still preserves the existing stable `identity_fields_forbidden` response and
  authorization ordering.
- `onUnauthorized` is a single replaceable callback hook; it does not perform
  navigation itself. Task 7 should connect it to the auth store redirect.
- Generated frontend build retains the pre-existing large-chunk warning.
- The full suite retains only the existing Starlette/httpx and Alembic
  deprecation warnings.
